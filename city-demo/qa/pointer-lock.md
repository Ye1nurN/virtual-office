# Захват мыши в первом лице — 2026-10-01

- При включении первого лица кнопкой или V общий контроллер города и встроенного офиса вызывает Pointer Lock из пользовательского события.
- В захвате поворот использует `movementX/movementY` без зажатой кнопки и не дублирует дельты из `pointermove`.
- Esc освобождает курсор. Клик по сцене повторно запрашивает захват. Возврат к виду сверху, открытие блокирующей панели, ввод текста, потеря фокуса, скрытие вкладки и удаление сцены освобождают мышь. После потери захвата очищаются клавиши движения.
- Сенсорное управление и отказ браузера сохраняют прежний поворот перетаскиванием. Позднее завершение запроса не захватывает мышь после выхода из сцены.
- Подсказка показывает «Мышь · осмотр / Esc · курсор» при захвате и приглашение к клику после освобождения. Диагностика доступна в `canvas.dataset.mouseLook` и `mouseLockError`.

Проверена изолированная копия `5ef786d` с файлами этой задачи, без незавершённых изменений портфолио:

- `npm test`: 120 тестов прошли, включая пять новых сценариев Pointer Lock: движение без кнопок, освобождение и очистка обработчиков, отказ и повторная попытка, запоздалые Promise, сенсорный/неподдерживаемый режим.
- `npm run build`: успешно; предупреждение Vite о крупных чанках сохраняется.
- Встроенный браузер Codex: город, аптека и офис переключаются V туда/обратно. Перетаскивание в аптеке меняет yaw/pitch; Esc оставляет интерфейс доступным, панель гида открывается и закрывается. Ошибок JavaScript не зарегистрировано.
- Ограничение проверки: встроенный браузер отклоняет настоящий захват с `PointerLockError`, включая видимую вкладку и фокус canvas. Chrome недоступен в инструментах. Поэтому нативный захват и движение мыши без кнопки проверены тестами контроллера, но не подтверждены в обычном браузере. `pointer-lock-browser.png` показывает именно запасной режим, а не успешный захват.

API сверено с [MDN Pointer Lock](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API). Деплой Cloudflare отдельно не проверялся.
